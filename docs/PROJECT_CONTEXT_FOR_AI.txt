PART A — PURPOSE AND SCOPE
================================================================================================
A.1 One-sentence summary
  An interactive, terminal-based, fully validated and resumable pipeline that takes BULK RNA-seq
  reads (from public databases or local FASTQ files) all the way to differential-expression
  results (up/down-regulated genes), plots and a final HTML report.

A.2 Who it is for
  A biologist or student with basic Linux knowledge. The user never edits scripts: every step is
  a numbered menu with explanations. Advanced users can change every scientific parameter in a
  YAML configuration.

A.3 Design goals (from the original "master development prompt")
  - One launcher (./rnaseq_pipeline); modular code behind it.
  - Python does everything up to the gene count matrix; R does DESeq2 and everything after.
  - Strong validation at every stage: never report success just because a file exists.
  - Checkpoint + resume: an interrupted or crashed run continues without recomputing valid work.
  - Reproducibility: exact commands, versions, parameters, checksums are recorded.
  - Never silently guess anything scientific (experimental groups, strandedness, assembly,
    reference release, trimming) — the user confirms every decision.
  - Never overwrite raw data; never use sudo; never install or download large data without
    showing size and asking.
  - Handle large data (tens to hundreds of GB) by streaming and avoiding copies.

A.4 In scope for Version 1
  Bulk RNA-seq only: public (SRA/GEO/ENA) or local FASTQ input, NCBI dataset search, reference
  management (any organism), FASTQ validation, FastQC/MultiQC, quality gate, conditional fastp
  trimming, HISAT2 alignment, sorted/indexed BAM + QC, strandedness inference, StringTie2
  transcript quantification, featureCounts gene counting, validated count matrix, interactive
  experimental design, DESeq2, up/down gene tables, standard plots, optional GO/Reactome,
  HTML report, manifest.

A.5 Explicitly out of scope for Version 1
  - Web interface, cloud execution, schedulers (SLURM), multi-user, distributed computing.
  - Single-cell RNA-seq (10x Genomics, Drop-seq, Smart-seq, ...). The tool DETECTS and REFUSES
    it, because bulk methods give wrong results on barcoded/UMI single-cell reads.
  - Pseudo-aligners (Salmon/kallisto), STAR, interaction/time-course designs (planned later).

PART B — SCIENTIFIC BACKGROUND (THEORY)
================================================================================================
B.1 What bulk RNA-seq measures
  RNA is extracted from a tissue/culture (millions of cells pooled), converted to cDNA,
  fragmented, adapter-ligated and sequenced. Each sequenced fragment ("read", or a read pair for
  paired-end) is a random sample of an expressed transcript. The number of reads falling on a gene
  is proportional to (expression level × gene length × sequencing depth). Comparing counts between
  conditions, after normalising for depth, reveals differentially expressed (DE) genes.

B.2 FASTQ files
  4 lines per read: "@id", sequence, "+", quality string (one Phred score per base, ASCII+33).
  Phred Q = -10·log10(P_error): Q20 = 1% error, Q30 = 0.1%. Paired-end data = two files (R1, R2)
  whose records must be in the same order with matching IDs.

B.3 Quality control and trimming
  FastQC reports per-base quality, adapter content, overrepresented sequences, duplication, GC,
  N content. Adapters appear when the insert is shorter than the read length ("read-through");
  they prevent alignment and must be trimmed. Low-quality 3' tails can also be trimmed. Note:
  duplication and uneven base composition are NORMAL in RNA-seq (highly expressed genes, random
  hexamer bias) and are not by themselves reasons to discard data.

B.4 Reference genome and annotation
  Genome FASTA (chromosome sequences) + annotation GTF (where genes/transcripts/exons are). They
  MUST come from the same assembly (e.g. GRCh38) — mixing assemblies (GRCh37 annotation on a
  GRCh38 genome) silently assigns reads to wrong genes. Providers name chromosomes differently
  ("chr1" UCSC/GENCODE vs "1" Ensembl vs "NC_000001.11" RefSeq).
  Bacterial NCBI annotations describe genes as CDS features (few or no "exon" records) — counting
  must then use CDS.

B.5 Splice-aware alignment (HISAT2)
  Eukaryotic mRNA is spliced, so reads can span exon–exon junctions; HISAT2 aligns across
  introns. Known splice sites (from the GTF) improve sensitivity. They can be built into the
  index (needs ~60 bytes/bp of RAM: ~160–200 GB for human) or supplied at alignment time
  (--known-splicesite-infile), which is standard with small sensitivity loss. Bacteria have no
  introns: --no-spliced-alignment is used. Output: SAM → sorted, indexed BAM.

B.6 Library strandedness
  Stranded protocols keep which DNA strand the RNA came from. dUTP/TruSeq Stranded = "reverse"
  (read 1 is antisense), some ligation kits = "forward", older kits = "unstranded". Counting with
  the wrong setting loses ~half or nearly all reads, or mis-assigns antisense reads. It is
  inferred from data (RSeQC infer_experiment) and confirmed by the user; never assumed.

B.7 Quantification: gene counts vs TPM
  - featureCounts: integer read/fragment counts per gene → REQUIRED input for DESeq2, whose model
    needs raw counts.
  - StringTie2 (-e, reference-guided): transcript-level abundance as TPM/FPKM — useful for
    isoform-level views, but NOT used for DESeq2 (TPM is already normalised and not counts).
  Multi-mapping reads (e.g. rRNA repeats) are not counted by default.

B.8 Technical vs biological replicates
  Several sequencing runs of the same library (lanes) are technical replicates → their counts are
  SUMMED into one sample. Biological replicates (independent animals/cultures) are what DESeq2
  needs to estimate variability: at least 2 per group (3+ recommended).

B.9 DESeq2 statistics
  - Model: counts ~ Negative Binomial(mean = size_factor × normalised expression, dispersion).
  - Size factors (median-of-ratios) correct for sequencing depth/composition.
  - Dispersion estimated per gene and shrunk towards a trend (information sharing across genes).
  - A GLM with the design formula (e.g. ~ condition or ~ batch + condition) is fitted; the Wald
    test gives a p-value per gene for the contrast (e.g. Treatment vs Control).
  - Benjamini–Hochberg adjustment → padj (false-discovery rate).
  - log2 fold change (log2FC): +1 = 2× higher in the numerator group, -1 = 2× lower.
  - LFC shrinkage (apeglm) stabilises noisy fold changes of low-count genes; used for plots and
    ranking, while significance uses the standard (unshrunken) estimate.
  - Independent filtering and Cook's-distance outlier handling are DESeq2 defaults.
  - Pre-filter used here: keep genes with ≥10 reads in ≥ (size of the smallest group) samples.
  Definitions used (configurable):
     Upregulated   = padj < alpha AND log2FC ≥  t     (defaults alpha 0.05, t 1)
     Downregulated = padj < alpha AND log2FC ≤ -t
  Design validity: every group needs replicates; covariates must not be confounded with the
  variable of interest (if every batch contains only one condition, batch and condition cannot
  be separated — the design matrix is not full rank).

B.10 Exploratory statistics
  VST (variance-stabilising transformation; rlog alternative) makes counts comparable for PCA,
  sample-distance and correlation heatmaps (blind = TRUE for QC). PCA on the 500 most variable
  genes shows whether samples cluster by condition (good) or by batch (a problem).

B.11 Bulk vs single-cell (why single-cell is refused)
  10x Genomics single-cell libraries store per read-spot: an index read (8 bp), a cell-barcode +
  UMI read (28 bp) and the cDNA read (~90 bp). Correct analysis demultiplexes cells by barcode and
  collapses PCR duplicates by UMI (Cell Ranger, STARsolo, alevin-fry). Treating such data as bulk
  paired-end reads is wrong, so the pipeline detects single-cell metadata (ENA library_source
  "TRANSCRIPTOMIC SINGLE CELL", protocol words like Chromium/10x/Drop-seq) and stops.

C.3 Core engineering principles
  - Modules other than cli.py/workflow.py/design.py never prompt the user → reusable by a future
    API/web backend.
  - Outputs are written to *.partial / *.part / index.building and renamed only after validation.
  - A checkpoint is written only after post-validation. Checkpoint = outputs (SHA-256 for files
    ≤50 MB, size+mtime for larger ones re-checked by stage validators), params, and the
    fingerprints of upstream checkpoints. Fingerprints are CONTENT-based (not timestamps), so
    re-running a stage with identical results does not invalidate later stages. A stage is VALID
    only if all upstream stages are VALID (recursive cascade).
  - Raw data immutable (local FASTQ are symlinked by default, never written to).
  - One process per project (fcntl lock).

C.4 Python → R hand-over
  After the design is confirmed, Python writes results/deseq2/deseq2_params.json (paths, formula,
  variables, reference level, contrasts, thresholds, filter, plot options) and runs
  Rscript --vanilla R/deseq2_pipeline.R params.json (first with --validate-only at design
  confirmation). R prints [OK]/[ERROR] lines that Python relays; afterwards Python independently
  validates every R output (row counts, thresholds actually respected, plots exist).

PART D — THE WORKFLOW, STAGE BY STAGE
================================================================================================
Each stage: START → input validation → execution → post-validation → checkpoint (SUCCESS) or
explained FAILURE. Checkpoint files are named after the key in brackets (checkpoints/<key>.json).
"project_initialized" is written at project creation.

 1. DATA DOWNLOAD / IMPORT [data_acquired]
    ENA: HTTPS, resumable, MD5 verified. SRA: prefetch, vdb-validate, fasterq-dump --split-3.
    ENA without mirrored files / wrong file count for the layout → automatic SRA route.
    Pilot mode streams only the first N reads (test only; flagged everywhere).
    Refuses single-cell samples and runs with more than two reads per spot.
 2. FASTQ VERIFICATION [fastq_verified]
    Every record streamed: '@' header, '+' line, alphabet ACGTNacgtn., quality chars, equal
    lengths, complete records, gzip integrity (decompressor exit code), pairs read in lockstep
    (equal counts, matching mate IDs), Phred+64 warning. Cache avoids re-reading unchanged files.
 3. RAW READ QC [raw_qc_completed]
    FastQC (report must parse; its Total Sequences must equal step-2 read count) + MultiQC.
 4. QUALITY GATE [quality_assessed]  — DECISION
    Advisory statuses from configurable thresholds (Part G). User: accept recommendation / run
    fastp / skip / stop. If trimming is chosen, ALL samples are trimmed (uniform processing).
 5. CONDITIONAL TRIMMING + POST-TRIM QC [trimming_completed]
    fastp; trimmed files fully re-validated; read counts must equal fastp JSON; FastQC/MultiQC and
    assessment repeated. Invalid trimmed output stops the pipeline. Skipped if not chosen.
 6. REFERENCE PREPARATION [reference_ready]
    Download/link, checksum, FASTA+GTF validation, feature-type check (bacteria → CDS prompt),
    genome/annotation compatibility, samtools faidx, BED12, splice sites/exons, HISAT2 index
    (RAM-aware; plain index for intron-free genomes), index validation (hisat2-inspect names ==
    FASTA names). Existing valid index never rebuilt.
 7. ALIGNMENT [alignment_completed]
    hisat2 --dta [--known-splicesite-infile | --no-spliced-alignment] | samtools sort; quickcheck;
    index. Validation: sorted header, index, flagstat, PRIMARY RECORDS == INPUT READS (×2 PE),
    HISAT2 total == FASTQ count, alignment rate ≥20% (warning <70%). Failed BAM → *.FAILED.bam.
 8. BAM QC [bam_qc_completed]   samtools idxstats/flagstat/stats + MultiQC.
 9. STRANDEDNESS [strandedness_determined] — DECISION
    RSeQC infer_experiment on 200k reads/sample; ≥80% one orientation → stranded; balanced →
    unstranded; else undetermined → user must choose. Stored with source and confidence.
10. STRINGTIE2 [stringtie_completed]  -e reference-guided TPM (can be disabled, e.g. bacteria).
11. featureCounts [featurecounts_completed]
    -t exon|CDS -g gene_id -s 0/1/2, PE: -p --countReadPairs -B -C. Validated strictly; gene
    count must equal the GTF gene count; warning if <30% assigned.
12. COUNT MATRIX [count_matrix_completed] — DECISION (sum technical replicates?)
13. EXPERIMENTAL DESIGN [design_confirmed] — DECISION
    Assign conditions (one by one, by text pattern, from TSV, or by choosing a public metadata
    field), covariates, formula, reference level, contrasts. Validated (replicates, valid R
    names, full rank) in Python and in R. Stored with the metadata SHA-256 (edits after
    confirmation are detected).
14. DESeq2 [deseq2_completed] — DECISION ("Proceed to DESeq2?" after a transition record)
15. REPORT + MANIFEST [report_generated]

Samples that fail a step: listed with reasons; the user may continue without them (≥2 remain)
or stop. Re-running a step retries the samples that failed in it.

PART E — DATA SOURCES

Data-input menu:
  1 Search NCBI for a dataset   GEO series or SRA runs by keywords + fields. Field menus come from
                                NCBI einfo ("Show searchable fields (indexes)" lists them for gds,

                                SuperSeries collect their sub-series.

warnings (mixed organisms/layouts, non-RNA-Seq, multiple runs per sample, SINGLE-CELL). Then

NCBI etiquette: email + optional API key in config (3 → 10 requests/second).

  folder holds several; index prefix optional.
F.5 Main menu 5 "Manage Reference Databases": catalog + store listing; Download and prepare a
  reference NOW (no project needed); change a project's reference; delete a prepared reference
  (type the folder name to confirm).
F.6 Compatibility checks: shared chromosome names (chr-prefix diagnosis), annotation coordinates
  within chromosome lengths (catches assembly mismatch), declared assemblies equal, GTF header
  build matches; override only by typing OVERRIDE (recorded).
F.7 Bacteria: annotation with few exons but many CDS → prompt to count CDS; StringTie2 disabled;
  plain HISAT2 index (empty splice-site file would crash hisat2-build); --no-spliced-alignment;
  BED12 for RSeQC built from CDS.
F.8 RAM rule for the HISAT2 index: splice sites in index only if ~60 bytes/bp fits in 90% of
  available RAM; otherwise plain index (~2.8 bytes/bp; human ≈ 8 GB) + sites at alignment.

    GC deviation >10 review; reads <1,000,000 review

    min length 25
  reference_store ~/rnaseq_references · hisat2_build.use_splice_sites_in_index auto
  hisat2: dta true, use_known_splice_sites true · alignment rate warn 70 / fail 20
  strandedness auto (inference: stranded ≥0.80, unstranded diff ≤0.10, undetermined >0.50)
  stringtie_parameters.enabled true, reference_guided_only true
  featurecounts: feature_type exon (CDS for bacteria), attribute gene_id, no multimappers,

  min_count_filter 10 reads in smallest_group samples · independent_filtering, cooks_cutoff true
  lfc_shrinkage apeglm · transformation vst · top_n_genes 50 · heatmap_max_genes 500
  plot_formats png+pdf, 300 dpi · annotation.enabled false (GO/Reactome optional)
  storage: warn <50 GB free, ask if free < 1.5× estimate, cleanup ask

  4 Manage Dependencies / Environment · 5 Manage Reference Databases · 6 View Previous Reports ·
  7 Pipeline Configuration · 8 Exit

  1 Continue pipeline (asks for missing data/reference first; offers retry/replace if all samples

    re-include · 5 Choose or replace the data source · 6 Change reference · 7 Experimental design ·
  8 Clean up intermediate files · 9 Dry run · 10 Return to main menu

  1 Start · 2 Review settings · 3 Change settings · 4 Validate inputs again ·
  5 Return to the project menu · 6 Cancel. If the step cannot start, pressing Start explains why
  and returns to the project menu (no loops).
H.5 Example session (bulk yeast, low vs high glucose, 2 vs 2, ENA SRR14208246-49)
  1 → name → Enter → Data input 4 → "SRR14208246 SRR14208247 SRR14208248 SRR14208249" → all →
  1 (full) or 2 (pilot) → Organism 3 (yeast) → source 2 (Ensembl) → 1 → y → n (no GO) → 1 (all
  samples) → y (start) → press 1 on each step screen → quality gate: 1 (accept) → strandedness:
  Enter (confirm) → design: 2 "High-glucose"→High, 2 "Low-glucose"→Low, 7 baseline High, y, 8, y →
  DESeq2: y → report. Expected biology: glucose-repressed genes (ADH2, FBP1, PCK1, JEN1, SUC2) up
  in low glucose.
H.6 Timings (12 cores): download dominates (25 Mbps ≈ 11 GB/h); human index 1–2 h once;
  alignment ~20–40 min per 40M-read human sample; DESeq2 minutes.

PART J — SAFEGUARDS, ERROR HANDLING, RESUME, RECOVERY
================================================================================================
  - No shell: commands are argument lists; empty arguments rejected; paths validated; project and
    sample names restricted; accessions validated by regex; path traversal blocked.
  - Pipefail semantics for hisat2 | samtools sort; timeouts; Ctrl-C terminates the process group
    and partial outputs are never used.
  - Every failure prints STATUS: FAILED, Stage, Sample, Problem, Likely cause, Recommended action,
    and is logged with the exact command, exit codes and log path.
  - Resume: status table (VALID / INVALID + reason / PENDING); valid stages are re-verified, not
    recomputed; valid per-sample BAMs are not re-aligned.
  - Recovery: projects without samples/reference are asked for them; all-failed samples → retry or
    replace; replacing data keeps downloaded files and invalidates dependent checkpoints.
  - Storage pre-flight: refuses when free < estimate, asks when borderline; cleanup offers only
    intermediates whose downstream outputs are validated (never raw data, references, BAMs).
  - System checks: FAT32 refused (4 GB file limit), 9p/Windows mounts warned, RAM/CPU warnings.
  - Bad --config path/YAML → clear error (no traceback).

  BAM/SAM   binary/text alignment files · BED12 transcript model format used by RSeQC

  SRR/SRX/SRP/PRJNA  run / experiment / study / BioProject accessions
  Strandedness  unstranded / forward / reverse library orientation
  TPM       transcripts per million (StringTie output; not DESeq2 input)
  UMI       unique molecular identifier (single-cell) · VST  variance-stabilising transformation
